# ADR-001. Modelo OData V4 con `autoExpandSelect`

Estado: aceptada.

## Contexto

El servicio de avisos de mantenimiento es un servicio RAP publicado como OData V4. La aplicación necesita:

- Una lista con búsqueda, filtros, ordenación y recuento resueltos en el servidor.
- Un detalle que muestra el aviso y sus composiciones (operaciones, repuestos y adjuntos).
- Edición con borrador, con envío automático de cada cambio.

El tipo `RequestsType` tiene más de cuarenta propiedades, entre ellas las de borrador y las de control dinámico. Cada pantalla usa solo una parte.

El modelo OData V4 de SAPUI5 no ofrece operaciones imperativas de lectura: los datos se obtienen a través de bindings y contextos. Sin selección automática, cada binding tendría que declarar a mano sus parámetros `$select` y `$expand`, y habría que mantenerlos sincronizados con las vistas.

## Decisión

El modelo por defecto de la aplicación es `sap.ui.model.odata.v4.ODataModel`, declarado en el `manifest.json` sobre el origen de datos `mainService`, con estos ajustes:

| Ajuste | Valor | Motivo |
|---|---|---|
| `operationMode` | `Server` | Los filtros y la ordenación se resuelven en el servicio |
| `autoExpandSelect` | `true` | El modelo calcula `$select` y `$expand` a partir de lo que usan las vistas |
| `earlyRequests` | `true` | Los metadatos se piden al arrancar, una sola vez |
| `groupId` | `$auto` | Las peticiones se agrupan y se envían sin intervención de la aplicación |

El bloque completo está en `docs/arquitectura.md`, apartado 5.1.

## Consecuencias

- Cada pantalla pide al servicio solo las propiedades que muestra. Las tablas del detalle usan rutas relativas (`_Task`, `_Part` y `_Attachment`) y el modelo genera el `$expand`.
- Una propiedad que no está ligada en ninguna vista no se carga. El código que necesite leerla desde un contexto debe asegurarse de que se ha pedido.
- Todo el acceso a datos se hace con bindings y contextos. La única excepción es el contenido binario de los adjuntos, encapsulado en `webapp/service/AttachmentService.ts`.
- Los cambios en un borrador se envían solos, como PATCH, en el grupo `$auto`. Las acciones invocadas después se encolan detrás.
- La lista y el detalle pueden compartir datos si el detalle se liga a un contexto obtenido del binding de la lista, lo que evita peticiones repetidas.
- El comportamiento exacto de cada API del modelo V4 se confirma en la referencia de la API de la versión del proyecto antes de usarla.
