# ADR-003. Flexible Column Layout

Estado: aceptada.

## Contexto

El planificador revisa muchos avisos seguidos: necesita ver el detalle de uno sin perder la lista, sus filtros ni su posición. El técnico y el operario trabajan sobre un aviso concreto y necesitan todo el espacio de la pantalla. La aplicación está declarada para escritorio, tableta y teléfono.

Las alternativas eran dos: navegación a página completa entre lista y detalle, que oculta la lista al abrir un aviso, y una disposición fija de dos paneles, que no permite ampliar el detalle a pantalla completa.

## Decisión

La vista raíz `App` contiene un `sap.f.FlexibleColumnLayout` con id `fcl`. El enrutador es `sap.f.routing.Router`.

| Elemento | Decisión |
|---|---|
| Primera columna | Vista `RequestList` |
| Segunda columna | Vista `RequestDetail` |
| Ruta `list` | Patrón `:?query:`. Lista en la primera columna |
| Ruta `detail` | Patrón `detail/{uuid}/{active}/:layout:`. Lista y detalle |
| Disposición | Propiedad `layout` del modelo `appView`, ligada al control `fcl` |

La disposición de las columnas y los botones de pantalla completa se resuelven con el ayudante semántico de `sap.f`.

## Consecuencias

- La lista sigue visible y conserva su estado mientras se consulta un aviso. El detalle ofrece las acciones de pantalla completa, salir de pantalla completa y cerrar.
- La disposición forma parte de la URL, en el parámetro `layout` de la ruta `detail`. Abrir directamente la URL de un aviso carga la lista y el detalle.
- La lista y el detalle están activos a la vez. Los cambios hechos en el detalle (edición, activación, descarte y acciones de negocio) deben reflejarse en la lista sin recarga manual, lo que se resuelve compartiendo los datos entre ambos (ADR-001).
- El `manifest.json` declara la librería `sap.f`, además de `sap.uxap` para la página de objeto del detalle.
- Las nuevas pantallas, como la vista de indicadores, necesitan su propia ruta y deben definir en qué columna se muestran.
