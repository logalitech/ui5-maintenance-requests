# HU-05. Adjuntos: ficheros e imágenes

Paso 48.

## Historia

Como operario, quiero adjuntar fotos de la avería y documentos al aviso, para que el técnico vea el problema antes de desplazarse.

## Criterios de aceptación

1. En modo edición, la sección "Adjuntos" ofrece "Añadir fichero" y "Hacer foto".
2. Se admiten imágenes PNG, JPEG y SVG, y documentos PDF, de 5 MB como máximo. Un fichero no admitido se rechaza con un mensaje antes de enviarlo.
3. Al añadir un fichero se crea el adjunto con su nombre y su tipo, se envía el contenido y la lista muestra el adjunto nuevo. Durante el envío hay un indicador de ocupación.
4. La lista muestra una miniatura para las imágenes y un icono para el resto, con nombre, tipo y un comentario modificable en edición.
5. Pulsar una imagen la abre ampliada.
6. Cada adjunto se puede descargar. En edición, se puede borrar.
7. "Hacer foto" abre la cámara del dispositivo, permite capturar y adjunta la imagen en JPEG. Si no hay cámara o no se concede el permiso, se informa y la aplicación sigue funcionando.
8. Al guardar el aviso, los adjuntos quedan disponibles en modo de visualización.
9. Todo el acceso al contenido binario está en `service/AttachmentService.ts`.

## Notas técnicas

- El contenido es una propiedad de tipo flujo (`Edm.Stream`) de la entidad `Attachment`. Se sube con PUT sobre la URL de esa propiedad en la instancia de borrador, con el tipo en `Content-Type`.
- El orden es fijo: primero se crea la entidad `Attachment` en el borrador, por la navegación `_Attachment` del aviso, y después se envía el contenido con PUT a `Attachments(AttachmentUUID=<uuid>,IsActiveEntity=false)/Attachment`.
- La petición necesita el token CSRF del modelo y la cabecera `If-Match`. Confirmar con la API cómo obtener las cabeceras del modelo (`getHttpHeaders`) y el ETag del contexto.
- La cabecera `If-Match` es obligatoria en la subida: sin ella, el servicio responde con el código `428`. Se admite el ETag del contexto del adjunto.
- El servicio fija `MimeType` con el valor de la cabecera `Content-Type` y `FileName` con el de la cabecera `Content-Disposition: attachment; filename="<nombre>"`. Sin esa cabecera, el servicio deja el nombre vacío aunque se hubiera informado al crear la entidad.
- El valor de un binding sobre la propiedad de flujo es su URL de lectura: sirve como origen de la imagen y como enlace de descarga. Confirmar con la API.
- Tras la subida hay que refrescar el contexto del adjunto.
- La cámara usa la API del navegador para dispositivos multimedia, que solo funciona en un contexto seguro (HTTPS o `localhost`).
- Confirmar con la API qué control de subida de ficheros está vigente en la versión 1.148.
- En el servicio se ha verificado la subida de un fichero de 3 MB. El límite de 5 MB y la lista de tipos admitidos los comprueba la aplicación antes de enviar.
- La secuencia completa, las cabeceras y los códigos de respuesta están en `docs/servicio.md`, apartado 7.
